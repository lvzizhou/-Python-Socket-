# 设计说明与报告提纲

## 研究目标

设计并实现可重复的 Socket 网络通信实验，通过真实请求证据识别服务不可达、应用延迟、UDP 应答缺失、DNS 错误及文件损坏。系统限定单机 Windows 回环环境，适用于网络编程教学。

## 架构

浏览器 → HTTP 控制接口 → 实验控制器 → DNS / TCP / UDP 服务端与客户端 → 诊断 → JSON 文件及页面。

控制面使用 Python 标准 HTTP 服务；实验数据面由 socketserver 并发服务器及 socket 客户端完成。RLock 防止场景切换互相干扰。服务仅绑定回环地址；每个 TCP 连接由独立线程处理，客户端线程池执行并发下载。

## 协议与关键算法

TCP：客户端发送长度前缀 JSON 请求 `{ "op": "download" }`；服务端返回长度前缀元数据（size、sha256），再返回长度前缀文件体。所有长度为无符号 32 位大端序。exact 循环接收直到预期字节数，遇到 EOF 立即报错；限制单帧不超过 2 MiB。

UDP：JSON 包含 token 和 seq，回显应答必须逐字节匹配；8 个串行请求，每次超时 120 ms。实验丢弃奇数序号，因此预期缺失率 50%。此实现没有 UDP 可靠传输重试，缺失是诊断证据。

DNS：手工构造事务号、问题区和 A 记录应答；域名 service.lab.test，TTL 0。仅教学所需单问题 A 查询，不提供递归服务或通用解析器。

诊断：解析地址与预期不符 → DNS_MISMATCH；正确 IP TCP 请求失败 → TCP_UNAVAILABLE；内容摘要不符 → FILE_CORRUPTED；完整传输大于 250 ms → RESPONSE_DELAY；UDP 未全数应答 → UDP_LOSS。多个证据可输出多个结论。250 ms 阈值用于本地演示，高负载可能误报，需要结合原始观测解释。

## 报告建议章节

1. 需求与课题意义。
2. Socket、TCP 字节流、UDP 数据报、DNS 和应用完整性原理。
3. 系统架构、协议格式和模块设计。
4. 服务端、客户端、并发与错误处理代码说明。
5. 正常与六种故障的实测表格、截图、JSON 和抓包证据。
6. 恢复实验、局限与改进。

实验表应包含场景、DNS 地址、直连结果、域名访问结果、UDP 收发、SHA-256、并发成功数、诊断结论。不要用样本耗时替代自己电脑上的测量值。

## 限制与后续扩展

当前无远程主机部署、拥塞控制实现、TLS、断点续传及持久化数据库。丢包与延迟在应用层模拟；文件损坏由程序主动产生。网络课程知识覆盖包括应用层协议、传输层、端口、连接、并发及抓包，未实现真实路由协议或链路层通信。
